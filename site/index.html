Pattern readout from this 100-app sample

  • REST is the dominant recorded interface: 89 records list REST as primary or sole API type.
  • API keys and OAuth2 appear 67 and 59 times in the auth labels; counts overlap because an app can support multiple methods.
  • 79 records are labeled free/trial, 19 paid/admin/partner and 2 local. Credential access—not API existence alone—is a major practical gate.
  • 46 records are labeled official MCP, 35 community, 15 none found, 4 unknown. MCP status is fast-changing and these are transcript labels pending broader validation.
  • 67 records are labeled build-now, 22 caveats, 9 outreach and 2 local. These are not verified current shipping decisions.

Prior comparison: after mapping the blind prior name NotebookLM to the dataset's NotebookLM (Gemini Notebook), 68/90 scored fields agree with the transcript labels. This is prior-to-output concordance, not accuracy against independent ground truth.

Independent source spot-checks

Checks below are claim-scoped. “Supported” means the cited official page supports the stated point, not that every field for that app is audited.

  1. Salesforce — supported_with_nuance
    OAuth 2.0 is used for REST API authorization; a free Developer Edition exists for testing; connected-app creation is restricted as of Spring 2026 and new integrations should use External Client Apps.
    Official evidenceDoes not independently validate the official MCP classification in the source row.
  2. DealCloud — supported_with_enterprise_gate
    REST APIs and OAuth2 client-credentials documented; DealCloud offers a hosted MCP endpoint, but Celeste licensing and tenant/admin permissions apply.
    Official evidenceThe source row's 'partner' access enum is too coarse: license and tenant authorization are demonstrated, not necessarily a partner-only API contract.
  3. LinkedIn Ads — supported
    OAuth 2.0 is used; Marketing API product permissions and application access require LinkedIn approval/vetting, with partner program restrictions for some scopes.
    Official evidenceThe source row is accurate at a broad level; individual API products have different approval rules.
  4. Pylon — supported_with_admin_dependency
    API tokens are bearer tokens and can be created only by users with token-management permission; if settings are unavailable, an admin must create or grant access.
    Official evidenceThe support article confirms admin permission dependency; it does not independently establish the commercial plan requirement.
  5. Brex — supported_with_admin_and_terms
    User token creation requires account/card admin access and acceptance of the developer API agreement.
    Official evidenceNo claim made here about availability of every Brex API product or sandbox coverage.
  6. Snowflake — supported
    Snowflake REST API supports key-pair authentication, OAuth, programmatic access tokens, and workload identity federation.
    Official evidenceThe prior's single summarized auth label omits PAT and workload identity federation; retain as multi-method auth.
  7. Neo4j — supported_with_scope
    Aura exposes a versioned REST API; Aura API credentials use OAuth 2.0 client credentials and are available across tiers; AuraDB Free and trial tiers exist.
    Official evidenceThis confirms the Aura cloud API, not every self-hosted Neo4j HTTP/Query API. 'REST' scope must be named explicitly.
  8. HubSpot — supported_and_refined
    HubSpot has an official remote MCP server at mcp.hubspot.com using OAuth/PKCE; it is distinct from the local Developer MCP server.
    Official evidenceTwo distinct official MCP products should not be collapsed into a single generic MCP flag.

  • Official-source checks use first-party documentation for the claims listed in the audit section.
  • Deterministic checks validate count, IDs, category balance, required fields and URL shape. They do not prove factual correctness.
  • Qwen's 20-app prior hash is preserved. The original scoring run has an app-name mismatch (“NotebookLM” vs “NotebookLM (Gemini Notebook)”); this repo's alias-repaired comparison yields transcript-label concordance only, not prior accuracy.
  • Auth, pricing/access and MCP status change over time. Evidence should be rechecked at implementation time, especially app-specific API product eligibility and tenant/admin gates.

Pipeline code and machine-readable JSON are in the public repository. The page is generated from data; it is not hand-edited to hard-code findings.

Reproducibility: python src/validate.py then python src/build_report.py. Source dataset and audit ledger are downloadable through the repository. No live credentials or private tokens are included.
